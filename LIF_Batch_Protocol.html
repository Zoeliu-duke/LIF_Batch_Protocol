What this does

For every image in one Leica .lif file the script: groups images by objective (e.g. 10x, 63x); uses Leica's merged image for tile scans (or, if you choose, stitches the raw tiles itself: measured overlap, linear blending); keeps the sharpest z-plane (or an average / max projection); denoises each channel (3×3 median, Gaussian σ 0.8 px); and shows every sample of a group with the same display range per channel, taken from one STANDARD sample. It saves panel figures, merges, TIFFs, comparison sheets, tables, check figures, and a ready-to-run Fiji macro.

This page writes the script for you. Everything in Settings (above) becomes the SETTINGS block at the top of the Script pane (right). Rename a channel once and every place that uses it updates.

Quick protocol

Not finished in one sitting? Press Save session (top right, or Cmd+S) to save everything on this page — settings, the script with any hand edits, what was read from the .lif, the half-written lab note and the run history — to one small .json file (keep it in the project folder). Next time press Open session and continue where you stopped. The note next to the buttons says whether you have unsaved changes.

1

Make a project folder (e.g. Documents/Claude code/ZL02) and put the .lif file in it. One .lif per folder. Copy fiji_macro_template.ijm from the image folder into it (the script needs it to write the Fiji macro).

2

Optional: let the page read the file. In Settings › 1, choose the .lif. This only fills in the form for you: sample names become dropdowns, and the channel count, objectives and colours are set, and your settings are checked against the file. Only the header (the list of what is inside) is read, in your browser; nothing is uploaded and no images are processed here. The real analysis happens in step 5, when Python reads the whole file from your folder. You can skip this and type names yourself.

3

Fill in the settings from top to bottom: channels, focus channels, overlays, the STANDARD sample for each objective, the control word, samples to exclude. Watch Ready to run? at the bottom of Settings until it shows no red items.

4

Copy the script. Press Copy script in the Script pane. Open IDLE with the imaging Python — not the IDLE app from Applications or the Dock (that one has no imaging packages: No module named 'numpy'). Double-click Open IDLE for imaging.command in the image folder (first time: right-click → Open → Open), or in Terminal:

~/.venvs/imaging/bin/python -m idlelib

In IDLE: File › New File, paste (Cmd+V), File › Save As… → your project folder → name it process_lif.py.

Paste into the new, empty window — not the "IDLE Shell" window that opens first (the one with the Python 3.12… line and >>>). Saving from the Shell puts that text and ... prompts into the file, and running it gives invalid syntax. If that happens, make a new file and paste again.

5

Run it: choose Run › Run Module in IDLE's menu (shortcut fn+F5 on a Mac; F5 alone is the Mac Dictation key — if it asks to enable Dictation, click Not Now). Messages appear in the IDLE Shell: loaded …, saved …, wrote processed/fiji_macro.ijm, extra: …, then done (~2 min for a 1 GB file). If you did not load the .lif here, the first run stops and lists the real sample names; put them into Settings › 5 and copy the script again. If the output folder already has results, the shell may ask you to type o, n or c (see Running again).

6

Check the results in the new processed folder with the QC checklist before using any figure.

7

Record it with the Lab note at the bottom of this column: fill in the experiment name, purpose, animals, tissue, antibodies and your results, choose First analysis or Re-analysis, attach processed/run_settings.json as the Run record, and press Generate lab note. The note is copied; paste it into your notebook or save it as a .txt file. It contains the exact settings of that run in readable form plus a machine-readable block, so Load settings (or Claude) can restore them later. Keep the exact process_lif.py next to the outputs.

Running again: overwrite or keep the previous results

Settings › 1 › If the output folder already has results decides what happens when you run the script again (script: IF_OUTPUT_EXISTS):

ChoiceWhat happens
Ask me each time ("ask", default)The IDLE shell asks. Type o = overwrite, n = new folder, c = cancel, then Enter.
Overwrite ("overwrite")The previous results in the folder are deleted first, then this run is written, so no old files are mixed in. Only a folder that looks like this script's output is ever deleted; otherwise the run stops.
Keep old, use a new folder ("new")Old results stay untouched; this run goes to processed_2 (then _3, …). The shell prints the folder name.

Without either choice, files with the same names would be replaced but files whose names changed (another Z mode, an excluded sample) would stay behind and mix with the new run. Both choices avoid that. Record which settings made which folder (Save settings). Fiji results inside the folder (processed/fiji/) are deleted too when you overwrite.

One-time setup

On this Mac the imaging Python is already installed at ~/.venvs/imaging. Test it in Terminal:

~/.venvs/imaging/bin/python -c "import readlif, skimage, tifffile; print('ready')"

The normal IDLE on the Mac does not have the image libraries. Always open IDLE with the command in step 4, or you will see No module named readlif.

On another computer

  1. Install Python 3.12 from python.org.
  2. python3 -m venv ~/.venvs/imaging
  3. ~/.venvs/imaging/bin/pip install readlif numpy scipy scikit-image tifffile matplotlib pandas pillow PyWavelets

Versions used for ZL01: Python 3.12.8, readlif 0.6.6, numpy 2.5.3, scipy 1.18.1, scikit-image 0.26.0, tifffile 2026.9.20, matplotlib 3.11.2, pandas 3.0.6. Windows: use %USERPROFILE%\.venvs\imaging\Scripts\python.exe.

Before imaging: what must match

  • Same laser power, gain, zoom, pinhole, bit depth, averaging and z-step for every sample you compare. Processing cannot fix acquisition differences.
  • Same channel order in every sample of the file.
  • Consistent names; controls share one word (e.g. noPrimary).
  • Prefer 12-bit; for dim channels raise that laser and add line accumulation ×2–4; image a uniform fluorescent slide per channel for flat-field correction.

Merged z-stack (projection) instead of one plane

By default each image is reduced to its sharpest single plane. To combine all planes instead, choose Average projection or Max projection in Settings › 6 (script: Z_MODE = "average" or "max"), copy the script again and run it.

  • Display ranges are recalculated from the projected STANDARD with the same rules, so samples stay comparable within that mode. Do not compare a projection with a single plane.
  • Figure titles say "average of 3 planes" (or "max of …"); image_summary.csv › z_mode records the mode per sample.
  • Keep both results: every run replaces the output folder, so give the projection run its own, e.g. processed_average (Settings › 1, Output folder name).
  • Clear forced planes (Settings › 6): a sample forced to one plane is not projected and becomes the odd one out. The script prints a NOTE if this happens.
  • Sum projection is not offered: samples with more planes would look brighter regardless of staining.
  • Caution for thick sections: if samples have different numbers or spacing of planes (ZL01: 3.4–17 µm apart, covering 7–22 µm), a projection mixes a different depth of tissue per sample. Single planes compare more fairly.
  • Fiji: the generated macro always contains the ranges for single plane, Average and Max; choose the same mode in its dialog.

What sets the channel order

The microscope does. When the image is saved, LAS X stores the channels in a fixed order (C1, C2, C3…) that follows the channel / sequential-scan setup used to acquire it. The script reads them in that order: row C1 in Settings › 2 describes the file's first channel, C2 the second, and so on. The names you type are labels only; they do not select a channel. If a row is in the wrong place, every figure is mislabelled.

To check the order: look at the channel list for that image in LAS X, or open the file in Fiji (Bio-Formats) and step through the channel slider. When you read the .lif in Settings › 1, each channel row also shows the colour LAS X gave that channel, and Ready to run? warns if a row's colour differs from the file's.

Setting up a new antibody panel

  1. Channels (Settings › 2): one row per channel in acquisition order. Loading the .lif creates the right number of rows with the file's colours; type the antibody-fluorophore names. Start with brightness 1.0 and black point "1st percentile of STANDARD".
  2. Focus channels (3): 1–3 bright, structured channels (nuclei, membranes). Used to pick the sharpest plane and align tiles.
  3. Marker-poor tissue (3): only needed for "marker-poor tissue" black points. Pick the channels that mark the cells of interest; background is measured where these are weakest.
  4. Overlays (4): 0–4 panels shown after the full merge. Recolour a channel within one panel when two colours clash (red on magenta → make one cyan).
  5. Negative controls (2): optional, per channel. If you included a control for an antibody (no primary, secondary only, isotype, or a section stained with everything except that antibody), type a word that appears only in those sample names in that channel's Negative control box, e.g. noCD8. That control is used only for that channel. Leave it empty for antibodies you trust without a control; use the tissue-based black points for them.
  6. Samples (5): STANDARD per objective and excluded samples (plus an optional "other control" word for controls not tied to one channel).
  7. Run once, look, then tune brightness and black points (next section). Keep the final settings for the whole study.

Choosing brightness and black points

First run of a new panel

  1. Neutral first run: press Neutral first run in Settings › 2 (brightness 1.0, black point "Percentile of STANDARD, 1" for every channel) and run once. This shows the data as recorded, with the same range for all samples.
  2. Pick a rule per channel (or press Suggested starting values): nuclear stain → percentile of STANDARD 1; clean negative control → control samples 95 (about control mean + 2 SD); no control, marker restricted to areas → marker-poor tissue 50 (adjust 20–75); no control, marker everywhere → percentile of STANDARD 25.
  3. Check: controls / known-negative tissue look black, and the dimmest real positive cells in the STANDARD are still visible. Raise the number if hazy, lower it if staining disappears; raise brightness if washed out, lower if faint. One channel at a time; "Keep old, use a new folder" lets you compare runs.
  4. Lock it for the whole study (Save settings) and state it in the methods. These are display choices, not positivity thresholds.

Brightness: display max = 99.8th percentile of the STANDARD × brightness. Higher number = dimmer channel.

Black point (display min; everything below is black). Several rules per channel are allowed; the highest wins.

After each change, copy the script again and re-run (Run › Run Module). display_style_comparison_<group>.png shows the effect of the black-point rules.

QC checklist

  • Stitching — look at tile borders in the figures and in stitching_review/ (one sheet per tile scan, all options side by side). Higher seam score = better-matching seams. Choose the default in Settings › 7 › Tile scans, and a different option for single scans below it. If you stitch here: overlaps in stitching.csv ~8–20 %, not at the edge of the search range; pair_ncc_min above ~0.5. Example: ZL01 (10x) — stitching here was better (Leica misaligned 5 of 7 scans); FE71 (63x brain) — Leica's merge was better.
  • Z — image_summary.csv › z_used (0 = first plane). Blurry or holes → force a plane in Settings › 6.
  • Display — comparison_<group>.png: STANDARD first; structures visible, background dark, not saturated; controls empty where expected; *_pct_saturated ideally < 1 %.
  • Figures — scale bars present; title shows the z choice; ranges printed at the bottom.
  • Marker check (if on) — marker sits on positive cells, not on negative cells. Auto-contrasted: inspection only.

Fiji

Plugins › Macros › Run… → processed/fiji_macro.ijm. Choose Batch (select the processed folder) or Active image, and the z handling (Sharpest / choose a slice — Fiji counts from 1 / Average / Max). Output: processed/fiji/. The macro has not yet been test-run in Fiji; note any error message and line number.

By hand, one image

Bio-Formats (Composite, Autoscale off) → Grid/Collection stitching (overlap 10, Compute overlap, Linear Blending) → Duplicate one slice or Z Project (Average/Max, not Sum) → 32-bit → Median radius 1 → Gaussian σ 0.8 (Scaled units off) → Lookup Tables → Brightness/Contrast › Set the numbers from display_ranges.json (never Auto or Apply) → Scale Bar → Stack to RGB.

Several .lif files

One folder per file, each with its own process_lif.py. Use the same settings for the whole study; only the file name, STANDARD and excluded samples change (Settings › Save settings / Load settings helps). Display ranges are recalculated from each file's own STANDARD, so brightness compares within a file, not between files. To compare across files, image with identical microscope settings and use fixed black points plus identical brightness.

Stitching, scan by scan: after a run, open processed/stitching_review/. It has one sheet per tile scan with Leica's merge, the fixed overlap and the registered stitch (plus your own numbers, if set) side by side: the whole scan and zooms on two seam junctions, all shown the same way. Each column says its seam score and the word to use; the one in your figures is green (USED). For any scan that should be different, add it under Settings › 7 › Stitching for individual tile scans: pick Leica / fixed / registered, or my own numbers. For your own numbers, start from the Registered numbers printed on that sheet and nudge them: overlap in %, drift in pixels (sideways shift between neighbouring tiles). Re-run and check the sheet again. stitching_seam_scores.csv lists all the scores. Choosing stitching per scan only changes where the tiles are placed, not any pixel values. The run record and lab note record every choice.

Fix the image

Find what you see, change that one setting, re-run, compare. Change one thing at a time, keep every change identical for all samples, and write down what you changed (Save settings or the lab note). Links go to the settings section.

Methods text (template)

Confocal images were acquired on a Leica [SP-series] microscope with HyD detectors using [10×/0.30] (tile scans) and [63×/1.40 oil] objectives. Images were processed with a custom Python pipeline (readlif, scikit-image, tifffile). Tile scans were merged in LAS X [or: stitched from the raw tiles by normalized cross-correlation of tile overlaps (initial overlap 10%) with linear blending]. For each image, the sharpest optical section was selected (maximal variance of the Laplacian of the combined [focus channels]). Each channel was denoised with a 3 × 3 median filter followed by a Gaussian filter (σ = 0.8 pixels). Display ranges were identical for all samples of a given magnification, derived from a reference sample; black points were set [as described]. Intensity measurements were performed on unfiltered images.
